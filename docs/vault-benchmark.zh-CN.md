# dsh-vault 参考调研与防护检查迭代

调研日期：2026-10-08。本轮目标：让 RiskProof 从“看到拦截结果”进一步走向“知道当前配置缺什么、下一步如何处理”。

## 公开信号与实现核对

[插件目录中文页面](https://awesome-dsh-plugin.com/zh/p/Ox0400/dsh-vault/) 本次显示 11 stars、近 30 天 9,907 次下载；[GitHub 页面](https://github.com/Ox0400/dsh-vault) 同样显示 11 stars。它是下载较高、star 数不高的例子，不能套用“高 star 导致高下载”的解释。旧调研中的下载数对应不同页面时间，不能拿来直接推断趋势；下载也不是独立用户数。

从作者 [README](https://github.com/Ox0400/dsh-vault#readme) 看到的产品链路是：加密保管凭据，提供工具与设置页，进一步覆盖健康检查、轮换、备份和迁移。凭据存储本身解决持续需求；设置页使当前状态可见，导入和备份降低使用门槛。后两句是产品推断，公开页面没有提供来源归因或留存数据。

源码核对重点为 [src/index.ts](https://github.com/Ox0400/dsh-vault/blob/main/src/index.ts)：`vault_health` 和 `vault_watchtower` 生成问题摘要；`VaultGateway.config` 返回访问模式等配置，设置页通过独立方法修改。这说明它把配置可见性、问题发现和处理动作连起来。这里只核对相关实现，没有复现它的加密存储、评分或宣称完成安全审计。

## 对 RiskProof 的取舍

| dsh-vault 的做法 | 本轮对应改进 | 边界 |
| --- | --- | --- |
| 健康问题列表 | 九项只读防护检查 | 检查有效配置，不扫描真实密码，不生成安全分数 |
| 设置页展示当前配置 | Web 概览可展开配置状态 | 沿用现有认证 RPC；没有新增可修改策略的远程接口 |
| 检查后提供处理入口 | doctor 文本建议与风险卡片建议 | 操作者通过 profile patch 修改；模型工具不能解除限制 |
| 工具与 UI 两种入口 | `/riskproof doctor`、`riskproof_report` 的 `health` 视图、Web 检查 | 复用报告工具，不增加模型工具数量或污染真实统计 |

新增诊断模块 `src/experience/health.ts` 根据只读快照生成结果。运行时只附加默认凭据标签和固定规则字段的比较结果，不把域名、路径、降密工具名称等配置值送到前端。风险建议使用固定中英文文案；未知规则引导用户查看 trace。

## 重要组合边界

作者明确说明 `vault_get` 会把完整凭据放入工具结果。RiskProof 默认输出保护会拦截带有凭据标签的结果；加密存储与进入模型上下文是不同边界。[dsh-vault 的限制说明](https://github.com/Ox0400/dsh-vault#security-boundaries--known-limitations)

当前 RiskProof 的来源推断对名称中含 `vault` 的工具保守地赋予 `SECRET`，因此 `vault_search`、`vault_health` 等无密摘要也可能被拦截。此判断可由本仓库的 classifier、`inferKindFromTool` 和输出策略代码推出；本轮没有安装 dsh-vault 或完成联合验收。

不能用“名字看起来像摘要工具”作为放宽凭据保护的依据，也不能通过全局关闭输出检查来宣传兼容。精确配置的可信降密只能移除继承标签，无法移除来源或实际输出重新检测出的标签。后续若做摘要互通，需要定义明确的可信输出协议、字段级审查和恶意同名工具回归，再单独验收。

## 使用与后续验证

操作步骤与九项检查解释见 [防护检查指南](protection-checks.md)。本轮验收关注：观察模式提示、输出标签缺失、严格预设被显式覆盖、无记录的诚实状态、旧快照降级、只读命令不增加记录，以及中英文窄屏布局。

增长验证继续沿用 [上一轮的 30 天计划](auto-review-benchmark.zh-CN.md#发布后-30-天如何判断是否有效)，增加人工记录两类反馈：用户能否通过 doctor 自行定位配置问题；风险建议是否帮助解决误报。没有用户行为遥测，也不把新功能与下载变化直接建立因果。
